# Extraction boundary

The reusable domain is finite-prefix forecasting, contextual combination and
sequence diagnostics. These procedures accept numerical histories and explicit
settings, and produce numerical results. They do not acquire a case, select a
customer, publish a manuscript or promote an artifact candidate.

The initial source moves preserve the originating kernels and their mathematical
adversarial tests. The application-specific forecast result dependency is replaced
with an independent five-field result type. Import relocation does not establish
parity by itself: core controls, diagnostic controls, installed-wheel execution
and comparison against the source implementation are separate checks.

The stable top-level calls validate complete finite histories, integer horizon
and seasonality, probability order, output shape and finite ordered forecast
columns. Lower-level extracted kernels retain historical numerical conventions,
including finite parameter grids and degeneracy floors. Those conventions are
documented rather than silently redefined during extraction. A later method
improvement requires a separately identified experiment and release.

ChronoScope retains source manifests, source reconstruction, case generators,
runtime/checkpoint policy, rendering and admission. Corpus-study partition policy
and its fixed model-selection protocol also remain application responsibilities.
They cannot become library defaults merely by copying a research script.

The product's historical evidence remains bound to the source that produced it.
Migration must archive the exact old source inputs and bind fresh executions to
the published library revision. Updating a recorded historical source hash to
hide a migration is forbidden. A successful package release alone does not close
the application's package-boundary requirement: it must consume that release,
remove its private distribution declaration and pass its own reproduction gates.
